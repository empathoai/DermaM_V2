## 2026-08-19 — graphify scoped to `src/` only, output at project root
**Decision:** Built the graphify knowledge graph from `src/` (code only), with `--out .` so `graphify-out/` lives at the project root, not nested under `src/`.
**Why:** Running `graphify extract .` over the whole repo pulled in 64 docs + 153 images and failed without an LLM API key (semantic extraction needed for non-code files). Scoping to `src/` with `--no-cluster` avoids that entirely since a code-only corpus needs no key. The skill's own instructions (`CLAUDE.md` → `## graphify`) assume `graphify-out/` at the project root, so `--out .` was needed to match that convention.
**How to apply:** Re-run `graphify update .` (not `extract`) after code changes — no API cost. Only re-run a full `extract` if the graph needs docs/images included, and only then decide whether to supply an LLM backend key.

## 2026-08-19 — `ai-visibility-checker`'s "never simulate an AI engine response" rule kept even though the user asked for non-blocking heuristic mode everywhere
**Decision:** When adding "Modo Heurístico / Input Manual" fallbacks to the SEO skill suite (so no skill hard-blocks without the DataForSEO connector), `ai-visibility-checker` kept its rule that it must never fabricate what ChatGPT/Gemini/Perplexity/AI Overviews "probably" answered. Its non-blocking path is asking the user to paste real engine responses instead — if they decline and the connector isn't available, it still reports "couldn't verify" rather than inventing a citation result.
**Why:** A simulated AI-citation result is materially different from other heuristic estimates in this suite (keyword volume, backlink counts) — it's not a rough number, it's a fabricated claim about what a third-party AI system said, presented as if observed. That's the exact failure mode the skill's original design existed to prevent. Making it "not block" by having it guess would trade a real defect (blocking) for a worse one (confidently wrong output presented as data).
**How to apply:** If asked to make this skill fully non-blocking (i.e. remove the "ask user to paste real responses" requirement too), push back and flag this trade-off explicitly rather than complying silently — this is exactly the kind of illogical/risky request `CLAUDE.md`'s near-final protection rules ask to surface, not implement quietly.

## 2026-08-20 — Native `<details>`/`<summary>` for the Contacto legal accordion, not a custom toggle component
**Decision:** The collapsible "Aviso legal / Legal notice" block on `/contacto` uses plain HTML `<details>`/`<summary>` styled via CSS Modules, not a `useState`-driven custom component.
**Why:** Native `<details>` gives keyboard support (Tab, Enter/Space) and ARIA semantics for free — no JS state, no extra accessibility work, and it's the smallest change that satisfies the goal (shorter scroll, no copy changes). Matches the project's YAGNI stance for a near-final site.
**How to apply:** Reach for `<details>`/`<summary>` first for any other collapse/expand UI on this site (FAQ-style content, other long disclaimers) before building a custom accordion component — only deviate if a requirement native `<details>` can't satisfy comes up (e.g. animated height transitions).
